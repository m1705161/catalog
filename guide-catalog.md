# OpenMetadata Data Catalog — local Docker guide

В этом гайде поднимаем локальный стенд OpenMetadata для знакомства с каталогом и последующей учебной демонстрации. На этом этапе мы **только запускаем платформу**: не подключаем Lakehouse, Managed-сервисы или другие источники, не загружаем данные и не настраиваем ingestion-тесты.

Используется официальный Compose-файл релиза **OpenMetadata 2.0.8**. Это локальная учебная конфигурация, не production-развёртывание.

## 1. Что запускается

```text
Браузер ── http://localhost:8585 ── OpenMetadata UI / API
                                      │
                       ┌──────────────┴──────────────┐
                       │                             │
                 MySQL (метаданные)          Elasticsearch (поиск)
                       │
                 Ingestion / Airflow
```

Compose поднимает пять сервисов: MySQL, Elasticsearch, миграцию схемы базы, OpenMetadata Server и ingestion-сервис с Airflow. Наличие ingestion-сервиса в Compose не означает, что источник уже подключён или что выполняется сбор метаданных.

| Назначение | Адрес на компьютере |
|---|---|
| OpenMetadata UI и API | <http://localhost:8585> |
| Проверка готовности Server | <http://localhost:8586/healthcheck> |
| Airflow UI | <http://localhost:8080> |
| MySQL | `localhost:3306` |
| Elasticsearch | `localhost:9200` и `localhost:9300` |

## 2. Предварительные условия

- Установлен и запущен Docker Desktop (либо Docker Engine с Compose V2).
- Docker выделено достаточно памяти для нескольких Java-сервисов и Elasticsearch. Для этого стенда желательно выделить не менее 8 ГБ памяти. В Docker Desktop объём памяти меняется в **Settings → Resources → Memory**; после изменения примени настройки и перезапусти Docker Desktop. С объёмом по умолчанию (часто 2 ГБ) Elasticsearch уходит в `unhealthy` и перезапускается.
- Свободны порты `3306`, `8080`, `8585`, `8586`, `9200` и `9300`.
- Есть доступ к GitHub и реестрам Docker-образов для скачивания Compose-конфигурации и образов.

Проверим, что Docker CLI видит работающий сервер:

```bash
docker version
docker compose version
docker info
```

В `docker info` должны присутствовать разделы **Server** и сведения о Docker Engine. Если показана ошибка подключения к Docker daemon, сначала открой Docker Desktop и дождись статуса **Running**.

На macOS/Linux проверить занятые порты можно так:

```bash
lsof -nP -iTCP:3306 -iTCP:8080 -iTCP:8585 -iTCP:8586 -iTCP:9200 -iTCP:9300 -sTCP:LISTEN
```

Пустой вывод означает, что слушающих процессов на этих портах не найдено. Если порт занят, останови соответствующий локальный сервис или контейнер до запуска OpenMetadata.

## 3. Создать папку проекта и положить файл

Создай отдельную папку под стенд и перейди в неё. Папка может лежать в любом удобном месте (например, в домашнем каталоге):

```bash
mkdir -p ~/openmetadata-catalog
cd ~/openmetadata-catalog
```

Всё дальнейшее выполняется из этой папки. В неё нужно положить [`docker-compose.yml`](docker-compose.yml) — Compose-файл из [официального релиза OpenMetadata 2.0.8](https://github.com/open-metadata/OpenMetadata/releases/tag/2.0.8-release). Версия файла закреплена, чтобы команды запуска были воспроизводимыми и не зависели от того, какая версия окажется последней. Скачать файл можно двумя способами.

Первый способ — скачать готовый файл из релиза:

```bash
curl -fsSL -o docker-compose.yml \
  https://github.com/open-metadata/OpenMetadata/releases/download/2.0.8-release/docker-compose.yml
```

Второй способ — открыть страницу [релиза 2.0.8](https://github.com/open-metadata/OpenMetadata/releases/tag/2.0.8-release), скачать `docker-compose.yml` из раздела Assets и сохранить его в созданной папке с тем же именем.

Если папка учебных материалов уже существует, можно вместо скачивания скопировать файл из неё:

```bash
cp "05-data-catalog-openmetadata-v2/docker-compose.yml" .
```

Проверь, что файл на месте и имеет ненулевой размер:

```bash
ls -la docker-compose.yml
```

Проверь корректность конфигурации:

```bash
docker compose config --quiet
```

Команда должна завершиться без ошибки. Если Docker Compose напишет предупреждение, что поле `version` устарело, для данного официального файла это предупреждение не мешает запуску.

## 4. Запустить OpenMetadata

Скачай образы и запусти сервисы в фоне:

```bash
docker compose up -d
```

При первом запуске Docker скачает несколько больших образов. Скорость зависит от сети; не закрывай Docker Desktop и дождись завершения команды.

Посмотри состояние сервисов:

```bash
docker compose ps
```

На первом старте база и Elasticsearch могут несколько минут инициализироваться. Миграционный сервис `execute-migrate-all` после успешной работы **завершается** — статус `Exited (0)` для него нормален. MySQL и Elasticsearch должны стать `healthy`; OpenMetadata Server должен перейти в рабочее состояние. Ingestion-сервис может стартовать дольше Server.

Если сервисы ещё запускаются, подожди минуту и повтори `docker compose ps`.

## 5. Проверить готовность

Проверка health endpoint Server:

```bash
curl -i http://localhost:8586/healthcheck
```

Ожидаемый результат — HTTP `200`. Это означает, что сервер OpenMetadata отвечает на запрос готовности.

Теперь открой в браузере:

<http://localhost:8585>

Должна загрузиться страница входа OpenMetadata. В этой локальной конфигурации включена саморегистрация (`AUTHENTICATION_ENABLE_SELF_SIGNUP=true`).

**Создай собственную локальную учётную запись** — через ссылку **Create Account** на странице входа, затем войди в неё. Не вводи рабочие или корпоративные пароли в локальный учебный стенд.

Что увидишь после входа — каталог настраивай с чистого листа, поэтому он пока почти пустой. Проверь, что слева доступны основные разделы: **Explore** (поиск по каталогу), **Data Quality**, **Govern** (глоссарий, теги, политики доступа) и внизу **Settings**. Увидеть эти пункты достаточно для проверки готовности UI.

> **Дефолтная учётка admin.** При первой миграции создаётся демо-пользователь `admin@open-metadata.org` с паролем `admin`. Это демо-учётка официального стенда; можешь зайти под ней, если не хочешь регистрировать собственную. Для учебных шагов дальше удобнее использовать свою запись.

**Что уже проверено после этих шагов:** Docker-контейнеры запущены, сервер отвечает на health endpoint, браузер открывает UI. Подключение источника данных и появление в каталоге таблиц — отдельная будущая часть занятия, здесь этого пока не делаем.

## 6. Что должно получиться в итоге

Проверь, что выполнены все пункты:

- [ ] `docker compose ps` — MySQL и Elasticsearch в статусе `healthy`, `openmetadata_server` работает, `execute_migrate_all` вышел с кодом `0`.
- [ ] `curl -i http://localhost:8586/healthcheck` вернул HTTP `200`.
- [ ] В браузере открылась страница входа `http://localhost:8585`; ты вошёл под собственной учётной записью или под демо-`admin`.
- [ ] В левом меню доступны разделы **Explore**, **Data Quality**, **Govern** и **Settings**.

Это и есть сдаваемый результат этого шага: работающий локальный каталог OpenMetadata. Скриншот открытого UI после входа — удобный способ зафиксировать готовность стенда.

## 7. Посмотреть логи при проблеме

Сначала проверь все сервисы:

```bash
docker compose ps
```

Логи OpenMetadata Server:

```bash
docker compose logs --tail=100 openmetadata-server
```

Логи базы и поискового движка:

```bash
docker compose logs --tail=100 mysql elasticsearch
```

Логи миграции схемы:

```bash
docker compose logs --tail=100 execute-migrate-all
```

Если команда `curl` сообщает, что соединение отклонено, проверь, что Server уже запущен и порт `8585` свободен. Если `docker compose ps` показывает `unhealthy` или постоянные перезапуски, проверь логи и доступную Docker память прежде, чем повторять запуск.

## 8. Остановить и запустить снова

Остановить контейнеры, сохранив состояние:

```bash
docker compose stop
```

Запустить остановленные контейнеры снова:

```bash
docker compose start
```

Удалить контейнеры и сеть, но оставить сохранённые данные:

```bash
docker compose down
```

При следующем `docker compose up -d` Compose создаст контейнеры снова и подключит сохранённые данные. Не запускай `docker compose down -v` и не удаляй `docker-volume/`, если хочешь сохранить локальное состояние.

## 9. Ограничения этого стенда

- Это учебный локальный запуск; не используй его как production-инсталляцию и не публикуй порты в интернет.
- Compose содержит демонстрационные настройки и пароли. Не подключай к нему корпоративные системы и секреты.
- Стенд пока не содержит источника данных, настроенных ingestion pipelines, тестов качества или специально подготовленных метаданных.
- В Compose может появиться предупреждение об устаревшем поле `version`; оно не относится к работоспособности сервисов.
